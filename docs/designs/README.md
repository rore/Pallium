# Designs

This directory keeps fuller design documents for Pallium.

Use it when a design topic needs more detail than the stable project context in
docs/context/.

For overall docs ownership, see ../README.md.

## Purpose

Each file here should capture one design thread, proposal, or analysis.

Good examples:

- core architecture proposals
- retrieval model proposals
- ingestion policy proposals
- tiered memory proposals
- integration analyses for a consumer or reference use case

## Conventions

- Prefer one design topic per file.
- Keep the filename descriptive and stable.
- If a design becomes accepted project direction, summarize the outcome in
  docs/context/decisions.md and update the relevant context docs.
- Do not force these files to stay short. They are allowed to keep reasoning,
  alternatives, examples, and tradeoffs.
