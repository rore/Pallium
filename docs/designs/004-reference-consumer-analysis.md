# Reference Consumer Analysis

## Goal

Capture how a real agent consumer can benefit from `Pallium` without making the
project itself depend on that consumer.

## Reference Use Case

A team-facing agent that already retrieves from source systems can use Pallium
as a derived memory layer.

The consumer already knows how to query systems of record. What it lacks is a
reliable memory of reasoning, tradeoffs, discussion outcomes, and historical
patterns.

## What Pallium Adds

Pallium can provide:

- preserved reasoning
- distilled decisions
- rationale recall
- investigation memory
- compact historical context
- later, pattern memory across time

## Where It Fits

The consumer flow becomes:

1. retrieve live evidence from source systems
2. query Pallium for derived memory
3. merge both in context assembly
4. synthesize a cited answer

So Pallium sits beside source retrieval, not instead of it.

## Most Valuable Inputs for This Use Case

The highest-value inputs tend to be transient or weakly structured material,
for example:

- discussions
- meeting outcomes
- bot investigation summaries
- selected cross-source syntheses

## Why This Matters

Without Pallium, the consumer can search.
With Pallium, the consumer can remember.
