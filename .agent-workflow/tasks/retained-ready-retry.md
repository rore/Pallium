# Retained recovery and hook delivery work

## Technical history

The work covers bounded recovery of authenticated retained clients, archive-aware wake eligibility, audited endpoint cleanup, retention cleanup, Windows acceptance-loop handling, and Codex hook capture/startup budgets. Retry behavior remains limited to resolved transient READY failures; REGISTER is never replayed. Hook capture remains a single combined request with bounded drain and one output. Startup time is charged against the existing 8-second budget with a 1-second host reserve.

The existing focused evidence records 534 passing affected nodes across separate runs: 185 hook tests, 343 caller tests, 2 protected contracts, and 4 redelivery tests. This is partitioned evidence, not a passing monolithic full-suite run. Current-head CI, complete local selector reconciliation, native acceptance, and installation acceptance have not been established. Historical host-side causes remain unconfirmed.

## CI caller-fixture correction plan

Independent plan review at `be4dc0c6` approved two fixture-only corrections. The deadline-entry test will use a hook-local deterministic clock and assert the exact remaining budget, unchanged reserve, ordering, and one start call. The protected competing-wake test will establish a fresh process entry immediately before each simulated hook invocation. This is equivalent fixture modeling: every payload, ACK, single-flight, and overtaken-wake assertion remains unchanged. Verification uses the existing PR `test` job. A controlled aged-module witness failed at the same missing-payload assertion with exhausted lock budget; this establishes the fixture boundary, not the physical cause of a historical host failure. The separate database setup deadline remains unexplained.
