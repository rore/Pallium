## Architecture assessment
The existing native tools offer neither an idempotency key nor atomic idle-only submission. Fresh idle/notLoaded does not prove an old notification cannot arrive later. Automatic re-notification therefore permits occasional extra empty wake turns while preserving single-owner attempts, active-claim exclusion, and suppression after payload ACK. This does not promise exactly-once model effects across a crash before ACK.

Protected contract requiring an exact user decision before edits: tests/behavior_contracts/test_codex_busy_wake.py currently asserts one accepted native submission across six 31-second recovery sweeps while the target remains idle and the payload remains pending. Proposed behavior permits another notification after cooldown and fresh eligibility if no claim/ACK exists. Busy targets, active claims, stale generations, unavailable custody, scope conflicts and terminal deliveries do not authorize a write. No protected test has been changed.
