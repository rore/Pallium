## Architecture assessment
The existing native tools offer neither an idempotency key nor atomic idle-only submission. Fresh idle/notLoaded does not prove an old notification cannot arrive later. Automatic re-notification therefore permits occasional extra empty wake turns while preserving single-owner attempts, active-claim exclusion, and suppression after payload ACK. This does not promise exactly-once model effects across a crash before ACK.

Historical pre-approval assessment: the protected test originally asserted one accepted native submission across six 31-second recovery sweeps, so the new behavior required exact task-owner approval. The approved and implemented contract now permits spaced retries after persisted cooldowns and fresh eligibility while the delivery remains pending and unclaimed. Busy targets, active claims, stale generations, unavailable custody, scope conflicts and terminal deliveries still prevent a write.
