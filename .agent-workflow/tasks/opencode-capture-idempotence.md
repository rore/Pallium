## Concrete completed-assistant contract

- Select assistants from the same after-latest-user range used by extractV2AssistantTurn. Never borrow an older valid assistant when the latest has an invalid ID. Require a valid native ID and finite public time.completed for every selected assistant; unfinished/malformed content stays retryable without reserving or writing. Do not compare completion timestamps with clocks or other events.
- Preserve existing aggregate text/work-trace extraction and the 20,000 UTF-16-unit maximum. Empty text, including tool-only extraction, produces no invalid /items write under its existing nonempty content contract; no placeholder/rendering or API change. A later completed tool-plus-text aggregate remains eligible. No new streamed snapshot versions.
- Revalidate existing live native ownership after history read and before capture, without copying PR297's separate initial ownership guard. Resolve actor and container once for both identity and POST. Source identity is `oc-assistant-` plus full SHA-256 of JSON.stringify(["opencode-assistant/v1", AGENT_REF, actor, container, sessionID, lastSelectedAssistant.id]). It excludes content, owner UUID, endpoint generation, timestamps, work refs and secrets; unchanged native capture retries/reload reuse the same backend key, unrelated scope/native IDs remain distinct.
- Add a per-lifetime in-flight Set of source identities. Reserve synchronously immediately before POST; suppress overlapping same-identity writes and always release the captured Set reference in finally. Recreate that set when the existing abort lifetime changes so old cleanup cannot delete a successor reservation. Different native assistant identities need not block one another. Change the single last-success marker to this scoped source identity, retaining bounded state.
- A successful capture requires the expected single /items receipt with nonempty source_item_id and current live ownership/lifetime. Failed/malformed/precommit/committed-response-loss replies release reservation and permit the same stable-ID retry; backend first-write-wins/uniqueness resolves any already-committed source. Do not update successor success state from a delayed old response. An already-issued request may commit; no compensating delete or false rollback claim.
