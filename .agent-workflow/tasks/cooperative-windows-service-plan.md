## Proposed behavior contract — review required

1. **Ownership before execution.** Existing hidden WScript launcher waits for a small Python observer in the existing service launch path. Observer owns one generation Job and restricted manual-reset stop event, acquires the single-generation launch exclusion, creates supervisor suspended, assigns it before resume, and propagates generation identity/event access. No breakaway is allowed; trampolines, API, workers and later descendants inherit containment. No child runs if creation/assignment/event/authority setup is incomplete. A partial suspended creation remains tracked until conclusively disposed without executing application code.
2. **One-way stop gate and complete ledger.** Any signal, controller request, stop predicate, fatal startup/recovery failure or deadline closes a monotonic gate. A same-generation restricted local mutex serializes controller event signaling, supervisor gate closure and each create/assign/resume admission; check latched stop again immediately before resume. Hold it only for short admission/signal actions, never while waiting for shutdown, a receipt or Job emptiness. Once closed the gate never reopens, including during token generation, readiness, retry sleep, helper startup and health recovery. A suspended creation racing close is retained and never resumed. Register every created root before readiness or callbacks, retain handles/exit results through all attempts and slot swaps, and retain every attempt's descendant ownership until terminal observation. Current slots are only scheduling pointers. Mutex acquisition timeout, abandonment or an unverified admission owner yields unknown and fails closed.
3. **Cooperative work boundary.** Event signal reaches supervisor and every child without HTTP. Worker, cleaner and snapshot reuse their own should_stop/between-operation checks; processor forwards the predicate. Idle/poll/backoff waits wake on event. In-flight operations finish via existing cleanup; no new work starts after observing stop. API schedules the selected-base OwnedServer.request_exit on its loop, including a request before the loop is captured or while startup is running; repeated requests are idempotent. Keep initialization/lifespan cleanup, native listeners and tracked storage operations intact.
4. **Controllable waits/admission deadline, no escalation.** One monotonic absolute transaction deadline bounds controllable waits/admission across preflight, mutex, stop, settlement, readiness and restoration. Synchronous native/filesystem operations may block and return late; no universal wall-clock return or cancellation guarantee is made. Retain ownership until the actual outcome is known, report terminal/unknown truthfully, and do not treat expiry as cleanup. Observations check before beginning and reject late results; mutations are explicit, never hidden in daemon read/watchdog threads. A late-created root is registered and retained before fallible cleanup; no replacement or automatic resume is admitted after expiry. The exact registered Task Scheduler action carries the same absolute deadline to the observer, and supervisor spawn gates inherit it. The caller can return UNKNOWN from a controllable wait while observer custody remains; a still-alive observer is not settlement. No taskkill, TerminateProcess, scheduled-task stop, Job close-to-kill or force. Never hold the spawn mutex through a drain/receipt/Job-empty wait. Omit final shutdown snapshot only on the selected managed path.

5. **Trustworthy terminal observation.** Private per-generation receipt discovery contains schema version, random generation ID, exact launch/config identity, observer and WScript identity (PID plus creation identity), supervisor identity and exit status, each retained attempt's terminal result, Job-empty observation, and terminal outcome. Observer atomically publishes the restricted receipt only after same-generation Job emptiness and known terminal observations. Controller opens/retains verified OS process handles before acting, validates receipt against generation/launch identities, and waits for the actual observer process **and actual WScript launcher** to exit; known Task Scheduler action settlement is additionally required for task-started generations. A receipt, PID disappearance, stopped task, empty port or empty Job alone is insufficient. Missing receipt, access denial, PID reuse, stale generation, result conflict, unfinished launcher or uncertain observation yields unknown.
6. **Outcome is separate from nonoverlap.** Clean means requested cooperative exit, all required known terminal results successful, Job empty, terminal receipt valid, observer exited, launcher/task settled. Known nonzero/crash is failed-but-settled, never clean. Empty Job proves only no remaining contained process; it does not prove ACK, commit, completed application work or successful cleanup. Unknown terminal status stays unknown even when nonoverlap is known. Never promise message ACK or transaction completion from a process exit.
7. **Continuous restart and bounded restoration.** First slice supports one continuous transaction retaining OLD Job/process pins through settlement and replacement admission. A later independent start after custody loss refuses/manual recovery; durable terminal metadata cannot reconstruct destroyed kernel objects. Unattended controller/owner-loss recovery is explicitly unsolved. No persistent custodian or terminal-attestation authority is added. Inside a continuous transaction, normal restart may start its intended new generation after clean or FAILED-BUT-SETTLED **old** generation only with positive entire-owned-set settlement, intact retained custody/identity and receipt validation, Job emptiness and actual observer/launcher/task exit. A failed old generation stays failed: recovery is never a clean/ACK guarantee. Unknown forbids replacement. If the intended new start fails, permit at most **one** same-config restoration start and spend that allowance atomically. Eligibility is either (a) definitive failure before any application launch/resume, with no live observer/launcher or suspended handle left, or (b) the failed **new** generation has known failed terminal results and the same entire-owned-set, receipt/custody and actual-exit settlement proof. A start exception is not proof of (a). Running-but-unready, readiness timeout, lost controller, unknown outcome and still-running old/new observer forbid retry. Restoration preserves exact interpreter, cwd, home, port, args and environment/config identity; it is a start retry, not a code/config rollback. A successful restoration reports recovery with the original failure, not ordinary restart success.
8. **Selected crash policy: no implicit kill-on-close.** Launcher/controller crash must not force active writes. Do not set kill-on-close in the first supported path. Lost custody yields UNKNOWN/manual recovery and no replacement; owner-loss recovery is not guaranteed. Future newly generated managed launcher/task metadata disables automatic Scheduler retry bypass; do not change the currently installed task/settings. Ordinary controller timeout/exit leaves the observer retaining Job custody, and an observer still alive is not completed settlement. Any later force, extra access/security mechanism or installed policy change requires separate review/approval.

Attempt retries need descendant settlement as well as a root exit. Recommended minimum: when an attempt fails and its descendants cannot independently be proved settled, close retry admission and cooperatively drain the entire generation. The one generation Job then proves nonoverlap. This changes new managed Windows five-attempt startup and per-slot retry behavior under the selected parent policy. Subordinate per-attempt Jobs could preserve more healthy-slot retry behavior, but add nested-Job compatibility and handle complexity and are **an unaccepted alternative, not necessary for the required no-unknown-overlap guarantee**. Never substitute root-only poll success for descendant settlement.

Receipt protection uses the same owning user's existing private runtime directory and a generation-specific event restricted to that user, with minimal query/signal rights; use random names, not predictable PID-only names. No new principal or access expansion is authorized. Metadata never confers authority. Receipt publication, process identity verification and actual-exit observation form one contract; stale/forged/unreadable evidence cannot advance it. No machine-wide process census is required.

Existing runtime recovery can write existing stores and dispatch already-authorized pending work; do not label it read-only or delete it just because its name contains recovery/initialize.
